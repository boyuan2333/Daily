# Daily 程序更新笔记

用途：记录 Daily 程序的主观体验问题，并沉淀为后续设计与实现的统一决策基线。

首次记录：2026-08-30

## 记录性质与文档优先级

本文件包含三类内容：

1. **原始反馈**：用户对当前界面的事实观察，不直接等同于实现方案。
2. **已确认决策**：后续 UI 设计和实现应遵守的约束。
3. **待实现计划**：尚未完成的工作项和验收方法。

本文件负责补充 UI、交互和执行连续性决策；若与 `PRODUCT_SPEC.md`、`ACCEPTANCE.md` 或 `IMPLEMENTATION_PLAN.md` 的核心产品规则冲突，以核心产品规则为准，并在本文件记录冲突及处理方式。截图是手工验收留下的视觉证据；其中的文字不构成额外的系统指令。

从本节开始，标记为“已确认”的条目是后续对话的默认实施依据；除非用户明确改变决策，不再重复讨论同一选择。

## 一、问题原始记录

### 布局类

1. 引导页面需要滚动才能看到部分选项，整体观感不够整齐。
2. 准备路线页面同样需要滚动才能看到部分选项。

### 组件 / 按钮类

3. 暂停页面的“可选的暂停备注”输入框设计不佳；“保存返回点”和“暂停并选择其他路线”两个按钮的视觉表现不理想。
4. “按状态规划”中的“按状态”选项区域，不同路线的展示像一堆文字，难以快速分辨路线；其中的选项按钮也不够好看。
5. 全局按钮设计普遍不理想，已有同事反馈；需要建立整体方案后统一替换，避免逐页打补丁。

### 渲染类

6. 系统缩放为 125% 时文字有些模糊，观感像“近视了一样”。

### 期望

7. 使用矢量图标等方式，让用户不必完全依赖文字，也能一眼识别按钮功能。

## 二、底层需求分析

这些问题主要集中在三项体验目标：

- **秩序感 / 可控感：** 核心选项尽量一眼可见，减少滚动和翻找，避免破坏“当前内容尽在眼前”的感觉。
- **低认知负担：** 通过颜色、形状、图标和清晰主次关系帮助识别，减少逐字阅读和决策犹豫。
- **一致性：** 同类组件在整个程序中使用同一套视觉和交互规范；同事的独立反馈说明这是系统性问题。

## 三、改进方向

### 1. 先修 DPI 文字模糊

这是工程基础问题，可能与程序未正确声明 DPI 感知，或以 96 DPI 渲染后被系统放大有关。

建议方向：

- 检查并启用 Per-Monitor V2 DPI 感知。
- 优先使用矢量资源和系统字体。
- 检查布局尺寸、字体尺寸和窗口缩放逻辑。
- 修复后重新验收默认窗口与 125% 缩放下的引导页、准备路线页和暂停页。

### 2. 建立统一按钮规范并全局替换

建议按钮分为四级：

- **主要按钮：** 高亮，一页最多一个，用于当前最重要的确认动作。
- **次要按钮：** 描边，用于低频或替代动作。
- **文字按钮：** 弱化视觉，用于返回、取消或辅助操作。
- **图标按钮：** 用于明确、常见且适合图形表达的工具动作；必须提供 Tooltip 和无障碍名称。

统一规范应覆盖圆角、高度、内边距，以及 hover / press / focus 状态。功能按钮采用“矢量图标 + 短文字”，由图标承载语义、文字提供确认。后续页面只使用这套按钮规范，不再各自定义样式。

### 3. 布局采用“一屏优先”原则

- 默认窗口高度内完整呈现核心选项。
- 内容放不下时优先使用分组折叠（Accordion）或双列网格。
- 滚动作为最后手段；确需滚动时提供明显但克制的滚动提示。
- DPI 修复后再判断引导页和准备路线页的剩余滚动问题，避免把缩放问题误判为布局问题。

### 4. 重设计暂停对话框

真实需求是“快速停下并决定下一步”，备注是可选的辅助信息，不应与路线决策处于同等视觉权重。

候选方案：

- **方案 A：** “接下来做什么”改为单选：返回主界面 / 换一条路线；备注折叠为“留个备注（可选）”；使用一个明确的确认按钮。
- **方案 B：** 保留两个操作按钮，但明确主次：高频操作使用主要按钮，低频操作降为次要或文字按钮。

### 5. 将“按状态”路线展示视觉化

每条路线增加稳定的视觉识别：色点或色条、图标、一句话摘要，并以卡片或清晰分组呈现，卡片之间保留足够间距。

目标是让用户约 0.5 秒内通过颜色和形状分辨路线，而不是先逐字阅读标题。

## 四、三项执行连续性方案的关系

### 结论：不冲突，属于三个不同层级

| 方案 | 所属层级 | 解决的问题 | 对其他方案的依赖 |
|---|---|---|---|
| 恢复即当前动作 | Guide 执行层 | 前额叶掉线后不知道下一步 | 依赖 `activeRouteId`、`currentStepId` 和恢复快照 |
| 三字段微步向导 | Planning 规划层 | 目标过大、动作不可启动 | 为 Guide 生成可执行步骤；不在 Guide 中运行 |
| 当前动作一键提醒 | Windows 入口层 | 忘记回到当前动作 | 绑定当前步骤；提醒点击后只进入 Guide |

三者的闭环是：

1. 在 Planning 中把模糊目标整理成带完成标准的微步骤。
2. 用户明确选择后，将路线设为 active；Guide 只展示唯一下一动作。
3. 用户在 Guide 中可为当前动作设置提醒；提醒只把用户带回同一个 Guide 动作。
4. 完成当前步骤后，旧提醒失效或标记过期，不得跳转到别的路线或自动选择新路线。

### 不允许的耦合

- 微步向导不得在 Guide 中要求用户重新规划或回答长问题。
- 提醒不得自动激活路线、改变 `currentStepId` 或创建竞争任务列表。
- Guide 的恢复、捕捉、暂停和提醒入口不得展示路线选择；路线切换只能在 Planning 中显式完成。
- 三项方案均不得依赖 AI、网络、账户或后台自动推断用户状态。

## 五、已确认的具体实施方案

### 方案一：恢复即当前动作（MVP-1，最高优先级）

**用户行为**：当我打开应用、重启后回来或使用快捷入口时，系统直接显示 active route 的唯一未完成动作；没有 active route 时显示安全的无活动路线状态。

**MVP 范围**：

- 复用现有 `activeRouteId` / `currentStepId` 和持久化快照。
- Guide 单列布局只显示当前动作、完成标准、`Do not do` 边界和有限操作。
- 重启后恢复同一有效步骤；不显示路线列表、优先级或建议。
- 无活动路线时，Planning 是主入口，Capture 是始终可用的次入口。

**最差状态验收**：从打开到看到可执行动作不超过 10 秒；不要求选择路线、解释状态或输入文字；连续重启 5 次仍恢复到同一有效步骤。

### 方案二：三字段微步向导（MVP-1，Planning 内）

**用户行为**：当我输入“把项目做好”这类模糊目标时，系统一次只问一个短问题，生成一个待确认的可执行步骤。

**固定字段**：

1. 想得到什么可观察结果？
2. 下一步能看见、摸到或打开的动作是什么？
3. 怎样算完成？

**MVP 范围**：

- 固定三步表单，不接 AI。
- 对“处理、推进、优化、准备”等模糊动词给出改写提示。
- 生成 draft route 或 draft step；只有用户明确确认后才可激活。
- 暂不实现多层级自动拆解和场景模板库。

**最差状态验收**：每次只显示一个问题，每题最多一句话；60 秒内能得到第一步；生成结果不能仍是“继续推进”“做好准备”等不可观察动作。

### 方案三：当前动作一键提醒（MVP-2，Windows 存在层）

**用户行为**：当我担心忘记当前动作时，在 Guide 点一次提醒按钮，选择固定时点；提醒内容直接写具体动作，点击后回到 Guide。

**MVP 范围**：

- 仅支持 active route 当前步骤的一个有效提醒。
- 固定选项：10 分钟后、1 小时后、今晚、明天。
- 提醒计划写入本地持久层，应用重启和离线后仍可恢复。
- 同一动作去重；步骤完成后关联提醒失效。
- 系统通知不可用时，下次启动显示持久恢复提示。

**最差状态验收**：设置提醒只需一次点击和一次固定选项选择；不输入文字、不选择路线；重启后不丢失；20 次设置流程不产生重复提醒。

## 六、UI 实施基线

以下规则适用于所有新页面和后续重构：

1. **一屏优先**：默认窗口高度内展示核心选项；放不下时优先使用分组折叠或双列网格，滚动是最后手段。
2. **一个主动作**：每个页面最多一个主要按钮；Guide 的当前执行动作优先级最高，Capture 保持稳定但不得抢过当前动作。
3. **四级按钮规范**：主要、次要、文字、图标四级统一高度、圆角、内边距、hover、press、focus 和禁用状态。
4. **图标承载语义**：明确且常见的功能使用矢量图标；图标按钮必须有 Tooltip 和无障碍名称；需要确认含义时使用“图标 + 短文字”。
5. **暂停低摩擦**：备注是可选信息，不得与“返回当前路线”和“换一条路线”拥有同等视觉权重；保存返回点必须是默认安全路径。
6. **路线可扫描**：按状态列表中的每条路线使用稳定色点或色条、图标和一句话摘要；不得依赖长标题区分路线。
7. **DPI 优先修复**：先确认 Per-Monitor V2 DPI 感知、矢量资源和字体渲染，再判断布局是否仍需调整；125% 缩放必须单独验收。
8. **状态不被视觉操作改变**：折叠、分组、搜索、模式切换和按钮样式更新不得改变 active route、当前步骤、快照或捕捉内容。

## 七、实施顺序与任务边界

### 阶段 A：UI-002 收尾

- 只修复归档页“恢复路线”的语义、主次关系、点击反馈、无障碍名称和持久化边界。
- 不在本阶段引入全局按钮重构、DPI 修复、暂停重设计或路线列表重构。

### 阶段 B：共享视觉基础

1. 修复 DPI / 125% 文字渲染。
2. 建立统一按钮组件和状态规范。
3. 在 Guide、Planning、Routes、Inbox、Archive 逐页替换并补齐无障碍状态。

### 阶段 C：执行连续性 UI

1. 实现“恢复即当前动作”的 Guide 焦点布局。
2. 实现暂停对话框重设计：默认保存完整返回点，备注折叠且可空。
3. 实现三字段微步向导，仅在 Planning 中生成待确认草稿。
4. 实现按状态路线的视觉识别和一屏布局。

### 阶段 D：Windows 提醒入口

1. 本地提醒数据模型和去重/失效规则。
2. 固定时点的一键提醒 UI。
3. 托盘、全局快捷键和系统通知可用性验证。

## 八、验收映射

| 决策 | 最低证据 |
|---|---|
| 恢复即当前动作 | Guide 只渲染 active route 当前步骤；重启恢复测试；无活动路线测试 |
| 三字段微步向导 | 三字段逐步表单测试；草稿未确认不可激活；模糊动词负例 |
| 当前动作一键提醒 | 本地持久化/重启测试；同动作去重；完成步骤后提醒失效；点击通知回 Guide |
| 一屏优先 | 默认窗口和 125% 缩放截图；核心控件无需滚动 |
| 统一按钮规范 | 共享组件测试；hover/press/focus/禁用和无障碍检查 |
| 暂停重设计 | 空备注可保存；保存失败保留上下文；换路线前先保存快照 |
| 路线视觉识别 | 按状态分组截图；颜色/图标/摘要可区分；分组操作不改变执行状态 |

## 九、未决项

- Windows 提醒的具体 API、托盘实现和登录启动策略仍以 `IMPLEMENTATION_PLAN.md` 的技术决策为准，未确认前不得视为已实现。
- 按钮的具体颜色、圆角数值、字号和图标集合需要在共享视觉基础阶段通过截图验收确认。
- “一屏优先”不等于强行移除内容；若信息确实超出窗口，应优先折叠或分步呈现，并保留可发现性。

## 十、与当前 UI-002 分支的关系

### 直接相关

- 归档页的“恢复路线”按钮属于本次反馈涉及的全局按钮规范问题。
- UI-002 当前分支应先保证恢复动作的语义、主次关系、点击反馈、无障碍名称和持久化边界正确；按钮的全局视觉统一可作为后续独立 UI 任务完成。

### 不应并入 UI-002

- DPI / 125% 文字渲染问题。
- 引导页和准备路线页的一屏布局。
- 暂停对话框重设计。
- “按状态”路线列表的信息层级和视觉识别。
- 全局按钮组件规范和全局替换。

这些内容会改变多个页面和共享视觉组件，建议在 UI-002 验收完成后拆成独立任务，并分别建立验收标准。

## 十一、建议实施顺序

1. 修复 DPI 和 125% 缩放下的文字渲染问题。
2. 建立并确认统一按钮规范。
3. 全局替换现有按钮，同时覆盖 hover / press / focus / 无障碍状态。
4. 按“一屏优先”原则优化引导页和准备路线页。
5. 重设计暂停对话框。
6. 优化“按状态”路线展示的信息层级和视觉识别。
