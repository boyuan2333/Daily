# Desktop UI Manual Acceptance

Run the unpackaged WinUI application from the Release publish output. Use a fresh local database for the first pass, then repeat the restart cases without clearing that database.

| Flow | Steps | Expected result |
| --- | --- | --- |
| No active route | Start with an empty store. Save a capture, then open Planning. | The capture remains visible in Planning; no route is created or active. |
| Create and activate | In Planning, add two prepared steps with completion standards and boundaries, save the draft, then make it active. | Guide shows only the first action, its completion standard, boundary, capture, pause, complete, and stuck controls. |
| Capture | Save a capture while a normal action is current. Close and restart. | `Capture saved.` appears only after saving; restart shows the same action and the capture in Planning. |
| Pause | Save a pause with an empty note. Close and restart. | Restart returns to the same action. The note is optional. |
| Fallback | On a route with a fallback, choose `I'm stuck`, then finish the fallback. | Only the pre-written fallback is shown. Finishing it returns to the original unfinished action. |
| Blocked | On a route without a fallback, enter one sentence and save it. Close and restart. | The return point remains saved; only return and pause-later controls are shown until returning to the action. |
| Final completion | Complete every step in an active route. Close and restart. | The route remains completed, no route is active, no other route is auto-activated, and the no-active capture entry remains available. |
| Route switch | From Planning, activate a different draft or paused route while another route is active. Close and restart. | The old route has a return anchor, and restart restores only the newly active route. |
| Paused route visibility | Keep one route active and at least two previously started routes paused. Open the Routes destination in Planning. | Paused routes are visible without passing through the route-creation form. Each shows its title, retained next-action context, pause time, and a clear resume command. |
| Exact paused-route resume | Resume a paused route that was stopped partway through, then return to Guide. | Guide shows the exact retained action. The user is not asked to choose a step or reconstruct context. |
| Guide route boundary | Open Guide while other unfinished routes are paused. | Guide shows no paused-route list, route comparison, replacement suggestion, or automatic switch. |
| Pause and choose another route | From Guide, invoke `Pause and choose another route`. First return without selecting a route; repeat and select a paused route. | Planning opens only after the return anchor is saved and focuses paused routes. Returning without selection restores the original Guide action. Selecting a route resumes its exact retained action. |
| Route-choice save failure | Cause the return-anchor write to fail, then invoke `Pause and choose another route`. | The application remains in Guide, reports the failed save, and preserves the active route and visible action. |
| Route grouping views | Open Routes for the first time, switch from `By status` to `By project`, leave Planning, and return. | The first visit uses status grouping. The later visit restores project grouping. All routes, statuses, anchors, and the active route remain unchanged; routes without a project appear under `Unassigned`. |
| Project membership | Assign an unassigned route to project A, move it to project B, then remove its project assignment. Check Guide after each operation. | The route appears exactly once in the appropriate project section or `Unassigned`. Its status, steps, return anchor, and Guide behavior never change. |
| Paused route disclosure | View several paused routes in Planning, expand one row, then collapse it. | Collapsed rows show title, 1–2 lines of next action, pause time, progress, and resume. The expansion adds completion standard, boundary, pause note, and fallback without opening an editor or changing any route state. |
| Capture placement and drawer | Open Guide, Planning, and the no-active-route state at desktop width, then repeat in a narrow window. Open, cancel, and successfully save Capture from each state. | Capture stays in the same bottom-bar position. Desktop uses a right drawer; narrow width uses a full-width panel. Save and cancel return to the same page, action, and scroll position. |
| Capture write failure | Enter capture text, cause the durable write to fail, and save. | The capture surface remains open, the text is preserved, a concise failure appears, and route and execution state remain unchanged. |
| Organized capture editing | Edit a capture, save the organized version, edit it again, then choose `View original`. Convert the entry to a route or step. | The Inbox prioritizes the organized text and marks the entry as organized. `View original` always shows the exact initial text and timestamp. Conversion does not discard or overwrite that original record. |
| Inbox list and detail | Populate Inbox with enough entries to scroll. At desktop width, select several entries and edit one. At narrow width, open an entry and return to the list. Repeat with an empty Inbox. | Desktop keeps previews and scroll position visible beside the detail pane. Narrow width uses list-to-detail and restores list position on return. Empty Inbox remains restrained and keeps Capture available. |
| Guide and Planning navigation | Switch repeatedly between Guide and Planning using the top segmented control. Open each Planning destination, then return to Guide. | The segmented control stays in one location and shows the selected mode. Planning shows Routes, Inbox, and Archive navigation; Guide hides it. Mode switching alone never changes route state. |
| Planning entry destination | Enter Planning normally for the first time, navigate to Inbox and scroll, return to Guide, then enter Planning normally again. Separately use `Pause and choose another route`, and repeat with no active route. | First entry opens Routes; ordinary re-entry restores Inbox position; pause-and-choose focuses Paused routes; no-active entry opens Routes. No entry path activates a route automatically. |
| No-active Planning hierarchy | Leave several routes paused with no active route and enter Planning. Repeat with no paused routes. | With paused routes, `Continue a previous route` leads and recent pauses appear first; create is secondary and nothing is preselected. Without paused routes, create becomes primary. Opening the page never activates a route. |
| Routes list and detail | At desktop width, select several routes, enter and cancel Edit, then save an edit. Repeat at narrow width and return to the list. Inspect archive, delete, and a protected step. | Desktop keeps the grouped list visible beside a read-only detail pane. Edit is explicit. Narrow width restores list context. Archive is secondary and reversible; delete is confirmed; protected steps are not silently removed. |
| Guide focus layout | Open a normal action, enter and exit fallback, and resize from desktop to narrow width. | One current action remains visually dominant. Completion standard and boundary stay visible; complete is primary; stuck and pause-and-choose are secondary; Capture stays separate. Fallback replaces rather than competes with the normal action. |
| Step completion feedback | Complete a non-final step successfully, repeat with a forced write failure, then complete a final step. | Success immediately shows the next action and a brief compact confirmation without a continue button or celebration. Failure leaves the original action unchanged. Final completion enters no-active state. |
| Language settings | Start with no language preference under Chinese and English Windows display languages. In Settings, switch among system, Chinese, and English, then restart. | The UI follows or remembers the selected behavior without requiring restart. User-authored content and route state never change. Language controls do not appear in Guide. |
| Planning search and filters | Search Routes by title, next action, and project in both grouping views. Search Inbox raw and organized text with each filter. Search Archive separately and try a no-match query. | Results remain in their existing grouping; Archive stays separate; no-match is restrained. Searching never changes, ranks, recommends, activates, archives, or deletes content. |
| Planning retention | Edit a route that has multiple steps, archive a non-active route, convert a capture to a route, and archive a capture. | Step order remains explicit; archived records remain listed as archived. A saved route step cannot be silently removed. |
| Failed writes | Run `dotnet test ExecutionContinuity.slnx --no-restore`. | The application-layer failure tests verify capture, final completion, and route switch do not change visible or durable state when SQLite commit fails. |
