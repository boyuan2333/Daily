# D1 信息架构草案 v1

- 状态：结构层草案，供 D-2 关键交互设计与 E-1 重构影响评估使用
- 目标：让用户在 Planning 中组织、安排和回顾多个工作对象，同时保留 Guide 的单动作执行连续性
- 设计边界：本文不做视觉稿，不决定尚未拍板的数据模型，不引入自动规划或自动激活

## 1. 架构总览

```text
Daily 应用
├── 顶部模式切换：Guide | Planning
├── Guide（引导）
│   └── 当前活动路线的一步：动作 → 完成标准 → 不要做边界
│       ├── Complete action（完成动作）
│       ├── I'm stuck（我卡住了）→ 单一 fallback 或暂停回到这里
│       ├── Pause and choose another route（暂停并选择其他路线）
│       └── 固定底部 Capture idea（捕获想法）
├── Planning（规划）
│   ├── Routes（路线）
│   ├── Calendar（日历）
│   ├── Inbox（收集箱）
│   ├── Review（回顾）
│   ├── Archive（归档）
│   └── Settings（设置，应用级入口）
└── Windows presence（Windows 外围存在）
    ├── Focus Mode（专注模式）
    ├── Desktop Widget（桌面挂件）
    ├── Tray（托盘）
    └── Global shortcut（全局快捷键）
```

核心判断：Guide 与 Planning 是同一个应用的两个 interaction modes（交互模式），不是两套产品；Routes、Calendar、Inbox、Review、Archive 是 Planning 的内容目的地；Focus Mode 是呈现方式，Widget/Tray/Shortcut 是 Windows 外围入口，均不拥有独立路线状态。

## 2. 主导航与板块职责

### 2.1 顶部固定模式切换

- 固定位置：应用顶栏同一位置显示 `Guide | Planning` 分段控件。
- Guide 选中时：隐藏 Planning 内部导航；只保留当前动作、必要上下文、执行控制和固定 Capture。
- Planning 选中时：显示内部导航 rail/板块列表，默认或恢复到合适的 Planning 目的地。
- 切换语义：只改变 presentation context（呈现上下文），不暂停、不完成、不激活、不切换路线。
- 失败保护：若当前正在进行 Capture 保存或暂停锚点写入，先保持当前表面直到写入成功/失败得到明确结果；不以导航切换掩盖失败。

### 2.2 Planning 内部导航

| 顺序 | 板块 | 主要问题 | 核心内容 | 是否改变执行状态 |
| --- | --- | --- | --- | --- |
| 1 | Routes（路线） | 我准备沿哪条路线推进？ | active/paused/draft 路线、Project、Step、恢复上下文 | 只有用户明确 Resume/Activate 才改变；查看与分组不改变 |
| 2 | Calendar（日历） | 工作按日期如何分布？ | 有日期任务与 Unscheduled 无日期候选区 | 只读投影或显式编辑日期，不自动排期/激活 |
| 3 | Inbox（收集箱） | 我刚才捕获了什么？ | raw capture、organized version、转换/归档 | 编辑整理或转换由用户触发；不覆盖 raw |
| 4 | Review（回顾） | 我做过什么、如何恢复过？ | 热力图、路线时间线、完成/暂停/Capture 历史 | 只读；不得改变当前执行状态 |
| 5 | Archive（归档） | 已归档内容在哪里？ | 已归档路线与 Inbox 条目、恢复/显式删除 | 恢复/归档是用户明确操作；删除需确认 |

Settings 不放入 Planning 内容板块中，作为应用级齿轮入口，负责 Follow system / 简体中文 / English 等偏好，不与执行控制争夺焦点。

## 3. Routes 结构

### 3.1 路线列表与详情

标准桌面宽度采用两栏：

```text
Routes
├── 工具行：By status | By project + 本地搜索 + 新建路线
├── 左栏：分组路线列表
│   ├── By status：Current / Paused / Draft
│   └── By project：各 Project / Unassigned
└── 右栏：选中路线详情（默认只读）
    ├── 标题、lifecycle、Project、Goal（若采用）
    ├── ordered Steps（有序步骤）
    ├── retained return context（保留返回上下文）
    └── Edit / Resume / Archive / overflow Delete
```

列表与详情同页联动：选中另一条路线只更新详情，不弹模态、不移动列表。详情默认只读，必须明确点击 Edit 才能改字段或步骤顺序。删除属于溢出菜单并要求确认；若删除会使有效快照引用无效，必须先让用户显式解决恢复路径，不能静默修复。

窄窗口切换为 list-to-detail（列表到详情）导航：进入详情前记录分组、搜索、滚动位置、展开状态和选中项；返回列表时恢复仍有效的上下文。

### 3.2 分组视图

- 首次访问默认 `By status`：Paused 置于主要位置，按最近暂停时间降序；Current 和 Draft 仍可见。
- 后续访问恢复用户最后选择的 `By status` 或 `By project`。
- `By project`：每个 Project 一个组；组内 active → paused → draft；无项目路线进入 `Unassigned`。
- 分组只改变投影，不改变 `activeRouteId`、路线生命周期、Step 顺序、快照或恢复位置。
- 搜索匹配路线标题、保留的下一动作和项目名，并保持当前分组结构；不按推断重要性排序。

### 3.3 无活动路线入口

当 `activeRouteId` 为空：

1. Guide 显示安全的 no-active-route state（无活动路线状态），主入口为进入 Planning 选择或创建路线，次入口为 Capture idea。
2. 进入 Planning 打开 Routes；若有 paused routes，顶部为 `Continue a previous route`，最近暂停者优先；`Create new route` 为次要操作。
3. 不预选、不自动恢复、不依据截止时间、优先级或 AI 激活路线。
4. Capture 成功后仍留在 no-active-route state，只新增 Inbox Entry。

## 4. Calendar 主视图

Calendar 是 Planning 的独立一级目的地，负责以日期降低寻找成本，而不是创建第二套执行状态机。

```text
Calendar
├── 日期范围/导航：日、周或月（具体尺度留给 D-2）
├── 有日期区域：按日期展示待办 Task / Step / Route 投影
├── Unscheduled（无日期）候选区：固定、清晰、与日期区域并列或相邻
└── 选中对象详情/明确编辑日期（不自动排期）
```

必须覆盖所有待办任务：有日期对象进入对应日期，无日期对象进入固定 `Unscheduled / 无日期` 区域，不隐藏，也不把它们伪装到某个日期下。无日期区可以是侧栏、底部收纳区或同页候选列，三者由 D-2 通过原型验证其寻找成本后选择。

Calendar 的排序是显式视图排序：日期 → 用户已定义的对象顺序；未定义时不得用推断优先级代替。点击对象可进入对应 Planning 详情；从 Calendar 直接进入 Guide 仍需遵守 activeRouteId 与明确激活规则。

## 5. Inbox 结构

Inbox 是 Planning 一级目的地，不是页面底部的一块杂项，也不是自动任务池。

```text
Inbox
├── 工具行：本地搜索 + All | Unorganized | Organized
├── 左栏：预览、capture time、organized 状态
└── 右栏：完整 organized content
    ├── View original（原始记录）
    ├── Edit organized version（编辑整理版本）
    ├── Convert to Route / Step（明确转换）
    ├── Archive
    └── overflow Delete + confirmation
```

首次编辑时从 raw text 复制到 organized version；之后只改 organized version。转换和未来用户触发的 AI 建议使用 organized version（若存在），但永不覆盖或丢弃 raw record。搜索同时匹配 raw 与 organized；普通结果不包含 Archive，Archive 自有搜索。

窄窗口采用 list-to-detail，返回恢复原列表滚动位置和选中条目。空 Inbox 使用克制的空状态，但固定底部 Capture 仍可用。

## 6. Review 回顾层

Review 与执行层分离，承载 R-1 推荐的“可恢复贡献热力图 + 路线回顾时间线”。

```text
Review
├── 时间范围：最近 12 周 / 今年（候选）
├── 可恢复贡献热力图
│   ├── 按日聚合已保存完成动作
│   ├── 空白 = 无记录，不是失败/欠债
│   └── 点击格子 → 当日动作明细
└── 路线回顾时间线
    ├── 动作完成
    ├── 暂停并保存返回点
    ├── 恢复
    └── Capture
```

热力图和时间线默认只读，切换范围、筛选和查看详情不改变 `activeRouteId`、`currentStepId`、路线生命周期或快照。Review 不显示连续天数、积分、徽章、排行榜、失败惩罚、生产力百分比或“应该做什么”的自动建议。暂停显示为可恢复上下文，Capture 遵守原始文本保护。

Guide 只提供完成后的短暂事实回执，例如“已保存，下一步是……”；不嵌入热力图、时间线或统计仪表盘。

## 7. Task / Project / Goal / Task Flow 在 IA 中的位置

### 7.1 层级基线

```text
Project（可选组织容器）
└── Goal（目标方向，是否独立实体待定）
    └── Task（用户工作单元）
        ├── Calendar 投影
        └── Route / Task Flow 编排
            └── Step（实际执行动作）
```

这里的层级是信息架构基线，不等于已经批准的数据库模型。Project 只组织，不拥有执行权；Goal 解释方向，不驱动排序；Task 是跨视图的用户语言；Route 提供执行上下文；Step 是唯一进入 Guide 的动作单位。

### 7.2 Task Flow

Task Flow 是 Planning 中可创建/编辑、可明确激活的固定顺序编排。典型路径：

```text
Planning → Task Flow 编辑 → 用户明确启动整组
→ 产生/选择一条 Route 实例 → Guide 逐步呈现每个 Step
→ 每次完成后推进下一 Step → 全组结束后保留历史
```

“一键推进整组”意味着用户不必在每一步重新选择下一任务，不意味着后台自动完成步骤、绕过完成标准或一次展示多项任务。Task Flow 不能在 Guide 中作为路线选择器出现；它只在 Planning 中被写入、复用和显式启动。

当前采用候选基线：模板 + 用户明确启动的 Route 实例。若 D-2/E-1 选择直接复制或同一路线重复运行，需同步修正术语与持久化边界。

## 8. Focus Mode 与 Desktop Widget

### 8.1 Focus Mode

Focus Mode 是 Guide 的 presentation variant（呈现变体），可从应用内显式进入，也可作为恢复时的聚焦呈现；它不是 lifecycle，也不是自动根据行为判断的状态。

- 隐藏主导航与不相关板块。
- 保留当前路线标题/进度、一个当前动作、完成标准、`Do not do`、完成/卡住/暂停和 Capture。
- 不显示路线列表、任务比较、Review 图表、AI 建议或第二个并列动作。
- 退出 Focus Mode 只恢复应用呈现，不改变路线执行状态。

### 8.2 Desktop Widget

Desktop Widget 属于 MVP-2 Windows presence，不在应用内部复制一套任务管理。

- 内容：活动路线标题、当前动作摘要、回到 Guide 的入口；最多允许明确设计的轻量动作，具体权限由 D-2 决定。
- 不提供：路线列表、跨路线选择、排序、自动规划、统计图表。
- 数据来源：只读当前 `activeRouteId` 与其 current Step；无活动路线时显示进入 Planning/Capture 的安全入口。
- 失联/关闭：Widget 不影响本地路线、快照或应用状态；应用重启后按 active-route recovery 规则恢复。

Tray 和 Global Shortcut 与 Widget 同属外围入口：快捷键只恢复当前 Guide；托盘只提供回到当前上下文，不在外围进行路线切换。

## 9. Planning / Guide 关系与关键流程

### 9.1 普通模式切换

```text
用户点击 Planning
  → 保存/保持当前呈现上下文
  → 打开首次 Routes 或最近 Planning 目的地
  → 不暂停、不完成、不改变 activeRouteId

用户点击 Guide
  → 读取 activeRouteId
  → 有活动路线：显示其唯一 current Step
  → 无活动路线：显示 no-active-route state
```

### 9.2 暂停并选择其他路线

```text
Guide：Pause and choose another route
  → 原活动 Route 写入完整 Pause Anchor
  → 写入成功后进入 Planning / Routes / Paused 聚焦
  → 原 Route 仍为 active，尚未替换
  → 用户明确 Resume 另一条 Route
      → 确认切换顺序并将旧 Route 置 paused
      → 新 Route 成为唯一 active
      → 回 Guide 显示新 Route 的锚点或当前未完成 Step
  → 用户取消/返回 Guide
      → 原 Route 与当前动作保持不变
```

若锚点写入失败，留在 Guide，保留当前动作并显示简洁错误。Guide 永远不显示候选路线。

### 9.3 完成、卡住、捕获

- Complete action：持久化成功后，非末步直接显示下一 Step；末步完成路线并清空 `activeRouteId`，转入 no-active-route state。
- Stuck：有 fallback 时只显示该单一回退动作；完成 fallback 后返回原 Step。无 fallback 时只允许一句话记录 block，自动保存锚点，并提供返回或暂停两种选择。
- Capture：从固定底部操作栏打开抽屉/窄屏面板；写入 raw text + timestamp 成功后回到原页面、原动作和滚动位置；失败保持输入与上下文。任何情况下不改执行状态。

## 10. AI、主动性与背景能力的位置

### 10.1 AI 建议级

AI 只出现在 Planning 的明确上下文中：Inbox 整理、Route/Task Flow 编辑或用户主动请求的分解建议。它的输出先作为可审阅草稿/建议，用户确认后才写入。Guide 不显示 AI 建议，不要求网络，不依赖 AI 才能完成 MVP-0 至 MVP-2。

禁止 AI 自动：选择活动路线、排序任务、安排日期、改变 Step 顺序、替换 fallback、修改 raw capture、在后台发送通知或推断用户状态。

### 10.2 主动性功能

“主动性”限定为界面提供稳定、低成本的入口，而不是系统替用户做决定：固定 Capture、恢复上次 Planning 位置、明确的暂停后聚焦 Paused、Widget/Shortcut 回到当前 Guide。这些入口可减少寻找成本，但不自动产生执行决策。

### 10.3 背景能力

背景能力只负责 Windows 壳层存在与本地可靠性：托盘、快捷键、可选启动、原子持久化、恢复与本地事件记录。它们不在后台改路线，不弹出打断通知，不创建自动任务，不改变 `activeRouteId`。

## 11. 影响范围基线（供 E-1，不是实现承诺）

| 区域 | 影响判断 | 处理方向 |
| --- | --- | --- |
| Domain state machine | 低—中 | 保留 activeRouteId/currentStepId、Snapshot、Capture 隔离；新增 Task Flow/Review 事件需避免第二状态机 |
| Persistence | 中 | 保留现有路线/步骤/快照/Inbox 记录；未来增加项目、日期、事件只追加迁移，不覆盖历史 |
| WinUI shell/navigation | 高 | 从 Guide/Planning 基础导航扩展 Routes/Calendar/Review/Archive 板块；重新映射旧 UI backlog |
| Guide surface | 低 | 保持单栏、单动作、fallback 替换、事实回执；Focus Mode 作为呈现变体 |
| Planning surfaces | 高 | 增加两栏 Routes/Inbox、Calendar、Review；所有写入仍限 Planning |
| Windows presence | 中 | Widget/Tray/Shortcut 读取当前上下文，不增添路线选择能力 |
| AI | 低（MVP-3） | 独立的用户触发建议流程，不成为早期依赖 |

旧 UI backlog（UI-002/005/006/008）在 D-2 定稿前冻结；定稿后按板块、状态隔离、响应式结构逐项重映射。E-1 负责把这份结构基线与实际代码做逐文件映射，本文件不提前假设实现文件名。

## 12. 开放问题清单

1. **Planning 一级板块是否包含 Review**：A. 与 Routes/Calendar/Inbox/Archive 并列（推荐，回顾不藏在任务内部）；B. 作为 Routes 二级页；C. MVP-2 才开放。
2. **Calendar 的主尺度**：A. 周视图为默认、日/月可切换（推荐）；B. 月视图为默认；C. 日视图为默认并提供周/月汇总。
3. **无日期任务区域形态**：A. 日历固定侧栏；B. 日历底部候选收纳区；C. 同页“Unscheduled”列（均满足同视图呈现，供 D-2 原型择一）。
4. **Task Flow 的实例关系**：A. 模板 + 新 Route 实例（推荐）；B. 复制为独立 Route；C. 同一路线重复运行并追加执行事件。
5. **Task 的详情页是否独立**：A. 不独立，使用 Route/Step 或 Inbox 详情（推荐，减少平行对象）；B. 独立 Task 页面，仅在进入执行时映射 Step；C. 仅对有日期 Task 提供独立详情。
6. **Review 的默认范围**：A. 最近 12 周热力图 + 最近 7 天时间线（推荐）；B. 当前 Route 全历史；C. 所有 Route 全历史。
7. **Focus Mode 的进入方式**：A. Planning/Guide 中显式按钮 + 可选快捷键（推荐）；B. 仅快捷键/托盘；C. 启动后始终进入。
8. **Desktop Widget 的操作权限**：A. 只读 + 回 Guide（推荐）；B. 允许完成当前动作；C. 允许完成与 Capture，但不允许路线选择。
9. **AI 入口位置**：A. Inbox/Route/Task Flow 编辑旁的用户触发按钮（推荐）；B. Review 的整理建议；C. 独立 AI 工作区。

## 13. D-2 验收检查点

D-2 的交互稿至少要能回答：

- 用户在标准桌面和窄窗口下，能否不经过搜索找到 Routes、Calendar、Inbox、Review、Archive？
- 无日期任务是否与有日期任务同在 Calendar 语境中，并且不伪装成某个日期？
- Guide 是否始终只显示活动路线一个当前动作？
- Pause、Capture、Complete 的成功反馈是否都在本地持久化确认后出现？
- Task Flow 的“一键推进整组”是否没有变成一次展示多个动作或自动执行？
- Focus Mode/Widget 是否减少寻找成本而没有制造第二个任务列表？
- Review 是否提供积累证据而不变成积分、连续打卡或压力仪表盘？
- AI 是否明确为建议级、用户触发、Planning 内、离线可不依赖？
