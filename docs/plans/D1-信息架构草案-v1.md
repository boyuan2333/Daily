# D1 信息架构草案 v1

- 状态：结构层草案；新增任务板块、独立任务页与桌面专注形态均待用户评审，不是现有实现声明。
- 目标：让用户在规划模式（Planning mode）中组织、安排和回顾多个工作对象，同时保留引导模式（Guide mode）的单动作执行连续性。
- 设计边界：本文不做视觉稿，不把候选结构写成已批准的数据模型，不引入自动规划或自动激活。
- 依据：`AGENTS.md`、`docs/PRODUCT_SPEC.md`、`docs/UX_DESIGN.md`、`docs/IMPLEMENTATION_PLAN.md`、`docs/research/R1-坚持与反馈机制调研.md` 与 D-0 已拍板方向；新 IA 仅提出候选，不修改上游规范。

决定状态说明：保留 = 当前规范已有的行为；建议 = 本 D1 推荐的结构，待用户评审；开放 = D-2 原型或 E-1 影响评估后选择。不可回退约束包括单动作、`activeRouteId` 唯一性、捕获（Capture）隔离、完整暂停锚点、回顾只读和 AI 建议级。

首次用词约定：路线（Route）包含有序步骤（Step），任务（Task）是步骤在 Planning 中的用户视角；项目（Project）可选组织路线，目标（Goal）说明希望达成的结果。执行快照（Execution Snapshot）承载暂停锚点（Pause Anchor）；预写回退（Fallback）只在卡住时呈现。捕获保存原始文本（Raw text）与时间，整理版本（Organized version）另存。完整定义与三份上游规范映射见 [概念地图](D1-概念地图与术语表-v1.md)。

## 1. 架构总览

```text
Daily 应用
├── 顶部模式切换：Guide | Planning
├── Guide（引导）
│   └── 当前活动路线的一步：动作 → 完成标准 → 不要做边界
│       ├── Complete action（完成动作）
│       ├── I'm stuck（我卡住了）→ 单一 fallback 或暂停回到这里
│       ├── Pause and choose another route（暂停并选择其他路线）
│       └── 固定底部 Capture idea（捕获想法）
├── Planning（规划）
│   ├── 任务板块（Task board）
│   │   ├── Calendar（日历主视图）
│   │   └── Tasks（任务页：只显示任务）
│   ├── 路线与任务流板块（Routes / Task Flows）
│   │   ├── Routes（路线列表与详情）
│   │   └── Task Flows（任务流蓝图与实例）
│   ├── Inbox（收集箱）
│   ├── Review（回顾）
│   └── Archive（归档，次级入口）
└── Windows presence（Windows 外围存在）
    ├── Focus Mode（专注模式）
    ├── Desktop Widget（桌面挂件）
    ├── Tray（托盘）
    └── Global shortcut（全局快捷键）
```

核心判断：Guide 与 Planning 是同一个应用的两个 interaction modes（交互模式），不是两套产品；Planning 以“任务板块”和“路线与任务流板块”为两类主要入口：前者回答当前有哪些任务、按日期如何找，后者回答沿哪条路线推进以及如何复用整组步骤。Inbox 和 Review 是独立内容板块，Archive 是次级保留入口；Focus Mode 是呈现方式，Widget/Tray/Shortcut 是 Windows 外围入口，均不拥有独立路线状态。

## 2. 主导航与板块职责

### 2.1 顶部固定模式切换

- 固定位置：应用顶栏同一位置显示 `Guide | Planning` 分段控件。
- Guide 选中时：隐藏 Planning 内部导航；只保留当前动作、必要上下文、执行控制和固定 Capture。
- Planning 选中时：显示内部导航 rail/板块列表，默认或恢复到合适的 Planning 目的地。
- 切换语义：只改变 presentation context（呈现上下文），不暂停、不完成、不激活、不切换路线。
- 失败保护：若当前正在进行 Capture 保存或暂停锚点写入，先保持当前表面直到写入成功/失败得到明确结果；不以导航切换掩盖失败。

### 2.2 Planning 内部导航

建议的四个主板块如下；这是信息架构候选，不是把每个板块都强制实现到同一 MVP。

| 顺序 | 板块 | 目的地 | 主要问题 | 是否改变执行状态 |
| --- | --- | --- | --- | --- |
| 1 | 任务板块 | Calendar（日历） / Tasks（任务页） | 现在有哪些任务、按日期如何找？ | 编辑日期只改元数据，查看不激活；只有明确开始/继续所属路线才改变执行 |
| 2 | 路线与任务流板块 | Routes（路线） / Task Flows（任务流） | 我准备沿哪条路线推进、如何一键推进整组？ | 仅用户明确 Resume/Activate/Start 才改变；查看不改变 |
| 3 | Inbox（收集箱） | Inbox | 我刚才捕获了什么？ | 整理/转换由用户触发，不覆盖 raw |
| 4 | Review（回顾） | 历史明细；候选热力图（Heatmap）/ 时间线（Timeline） | 我做过什么、如何恢复过？ | 只读，不改变当前执行状态 |

Archive（归档）保留为 Planning 的次级入口；Settings（设置）是应用级齿轮入口，不属于核心板块。板块与目的地的分工是：任务页只列任务，路线页管理 Route，任务流页管理蓝图/实例，日历投影同一批任务。

#### 任务板块：日历 + 独立任务页

- Calendar 是主视图，按计划日期显示所有待办任务，并固定展示 `Unscheduled / 无日期` 区域。
- Tasks 是显著、独立、只显示任务的页面；列表不混入项目、路线编辑表单、快照、回顾图表或 AI 长文。每条任务显示任务名、所属路线的必要上下文、准备状态、日期（若有）和进入对应 Planning 详情的入口。
- 任务页可以按稳定视图筛选或打开任务详情，但不提供越过当前步骤直接完成后续任务的按钮；真正执行仍回 Guide 的当前 Step。
- 无法形成可执行步骤的想法继续在 Inbox，不强行生成任务；已归档任务不出现在普通任务页。

#### 路线与任务流板块

- Routes 负责路线列表/详情、状态分组、项目归属、步骤顺序、暂停上下文和显式 Resume。
- Task Flows 负责可复用蓝图与历史实例；用户在这里明确 Start，生成/选择一条 Route 实例后进入 Guide。
- Route 与 Task Flow 不互相伪装：路线实例有独立快照与完成历史，蓝图修改不回写历史实例。


### 2.3 入口优先级与旧导航迁移

| 显式入口 | D1 候选目的地 | 与现有规范关系 |
| --- | --- | --- |
| 无活动路线进入 Planning | 路线与任务流 / Routes；有 paused 则“继续之前路线”为主、创建为次 | 保留恢复优先，不自动选择 |
| 暂停并选择其他路线 | 保存锚点成功后 Routes / Paused | 保留；优先于上次浏览位置 |
| 有活动路线时首次普通进入 Planning | 任务 / 日历 | 建议变更；现有 PRODUCT_SPEC §4 是 Routes，须评审后更新 |
| 后续普通进入 Planning | 恢复最近目的地、视图与位置 | 保留上下文；旧 Routes/Inbox/Archive 位置映射到对应新入口 |
| 用户直接点任务列表 / 日历等目的地 | 该目的地 | 明确导航只浏览，不自动激活 |

推荐“任务 + 路线与任务流 + 收集箱 + 回顾”，让任务排列方式共用一板块，同时把编排管理集中。备选是“日历 + 任务列表 + 路线 + 收集箱 + 回顾”平铺，入口更直接但板块更多；另一备选把所有管理放进任务板块，导航更少但路线恢复较深。IA-01 保留选择，所有方案都必须有显著独立任务页。

Archive 次级入口支持单独搜索与可逆恢复；恢复归档不是激活路线。Settings 保留跟随系统、简体中文和 English 选择，只改变界面语言与时间显示，不翻译或改写用户内容。

## 3. Routes 结构

### 3.1 路线列表与详情

标准桌面宽度采用两栏：

```text
Routes
├── 工具行：By status | By project + 本地搜索 + 新建路线
├── 左栏：分组路线列表
│   ├── By status：Current / Paused / Draft
│   └── By project：各 Project / Unassigned
└── 右栏：选中路线详情（默认只读）
    ├── 标题、lifecycle、Project、Goal（若采用）
    ├── ordered Steps（有序步骤）
    ├── retained return context（保留返回上下文）
    └── Edit / Resume / Archive / overflow Delete
```

列表与详情同页联动：选中另一条路线只更新详情，不弹模态、不移动列表。详情默认只读，必须明确点击 Edit 才能改字段或步骤顺序。删除属于溢出菜单并要求确认；若删除会使有效快照引用无效，必须先让用户显式解决恢复路径，不能静默修复。

窄窗口切换为 list-to-detail（列表到详情）导航：进入详情前记录分组、搜索、滚动位置、展开状态和选中项；返回列表时恢复仍有效的上下文。

### 3.2 分组视图

- 首次访问默认 `By status`：Paused 置于主要位置，按最近暂停时间降序；Current 和 Draft 仍可见。
- 后续访问恢复用户最后选择的 `By status` 或 `By project`。
- `By project`：每个 Project 一个组；组内 active → paused → draft；无项目路线进入 `Unassigned`。
- 分组只改变投影，不改变 `activeRouteId`、路线生命周期、Step 顺序、快照或恢复位置。
- 标准行保留路线标题、下一动作摘要、暂停时间、步骤进度与明确 Resume；单层只读展开显示完成标准、不要做边界、备注和预写回退，展开不编辑或换路线。
- 已完成路线不自动归档：建议在 Routes 提供“已完成”只读筛选入口，并可由任务页的完成记录或回顾明细进入其详情。归档路线只在 Archive，历史不会因活动列表只列三种状态而丢失。
- 搜索匹配路线标题、保留的下一动作和项目名，并保持当前分组结构；不按推断重要性排序。

### 3.3 无活动路线入口

当 `activeRouteId` 为空：

1. Guide 显示安全的 no-active-route state（无活动路线状态），主入口为进入 Planning 选择或创建路线，次入口为 Capture idea。
2. 进入 Planning 打开 Routes；若有 paused routes，顶部为 `Continue a previous route`，最近暂停者优先；`Create new route` 为次要操作。
3. 不预选、不自动恢复、不依据截止时间、优先级或 AI 激活路线。
4. Capture 成功后仍留在 no-active-route state，只新增 Inbox Entry。

## 4. 任务板块：日历主视图与独立任务页

共同候选模型见 [概念表](D1-概念地图与术语表-v1.md) §2、§3.11：任务（Task）是步骤（Step）的 Planning 投影，单任务使用单步路线（Route）。任务页与日历引用同一身份，不各建一份完成状态；项目（Project）与目标（Goal）只提供组织元数据。日期是新增候选属性，旧记录不补假日期。

### 4.1 独立任务页

```text
Planning / 任务
├── 明显的同级入口：日历 | 任务列表（可直接进入，不藏在路线详情）
└── 任务列表页
    ├── 本地搜索；待办 / 已完成；全部 / 按项目 / 按目标
    ├── 内容区：每行一个任务，包含动作、日期、准备状态
    └── 选中任务 → 只读任务详情；显式编辑或进入所属路线
```

“只显示任务”指内容区只列任务记录。项目/目标可作为分组标题和任务上下文，但不能插入项目卡、路线卡、收集箱原文、任务流蓝图、回顾图表或推荐。导航与固定捕获入口仍存在；要隐藏主菜单则进入专注模式。

默认显示所有未归档、未完成的步骤投影，包括草稿、活动及暂停路线中的任务；有日期和无日期混合可查。没有完成标准的草稿显示“尚未准备好”，编辑补齐后才能执行。候选稳定顺序为所属路线标题 → 路线身份 → 步骤顺序；按项目/目标时保留未分配组，不用推断重要性排序。分页或虚拟列表不得使无日期条目永久不可发现。

点击行只查看，不激活。对于多步路线中的后续任务，明确显示“继续所属路线（当前为……）”；不能勾选跳过前置步骤。独立任务可在 Planning 明确开始其单步路线。完成动作在 Guide 按完成标准提交；最终步完成后清空活动路线，返回安全空态。

### 4.2 日历主视图

```text
Planning / 任务 / 日历
├── 日 / 周 / 月；当前日期范围（建议默认周）
├── 当前范围的日期区域
│   ├── 有日期无时刻：当日全天行
│   └── 有日期有时刻：对应时间位置
├── 无日期（Unscheduled）区域：不受日期范围排除
└── 范围外待办入口：更早 / 更晚；可转全部任务列表
```

“所有待办”指同一任务集合均可发现，不是把所有日期挤在当前一屏。日历范围只限制有日期部分，无日期区始终同页可达；有过往计划日期且未完成的任务保持原日期，在“更早待办”入口可查，不自动挪到今天、逾期变红或开启提醒。完成与归档项默认不混入待办，完成筛选与归档入口保留历史。任务流尚未开始的蓝图步骤不生成假待办。

日期暂按计划日期 + 可选时刻的 C-05 推荐方案解释；若选择单独截止日期，需在 D-2 明确不同语义。日期编辑必须在 Planning 明确保存；拖放若采用也必须走同样写入确认规则。改变日期不改变路线内顺序、活动指针、完成状态或快照。

无日期呈现候选：

| 方案 | 放置 | 收益与代价 |
| --- | --- | --- |
| A（推荐） | 宽窗口固定侧栏；窄窗口同页日期区上方紧凑列表 | 无日期容易看到；占用日历空间，需验证长列表密度 |
| B | 日期区域下方固定无日期段 | 日期空间充分；需常驻锚点避免滚动后遗忘 |
| C | 同页可展开无日期抽屉，入口一直可见 | 更紧凑；多一步展开，发现性较弱 |

任何选项都不能把无日期任务藏进另一个一级分类。打开详情再返回时保留日期范围、无日期区展开状态、筛选与滚动位置。

## 5. Inbox 结构

Inbox 是 Planning 一级目的地，不是页面底部的一块杂项，也不是自动任务池。

```text
Inbox
├── 工具行：本地搜索 + All | Unorganized | Organized
├── 左栏：预览、capture time、organized 状态
└── 右栏：完整 organized content
    ├── View original（原始记录）
    ├── Edit organized version（编辑整理版本）
    ├── Convert to Route / Step（明确转换）
    ├── Archive
    └── overflow Delete + confirmation
```

首次编辑时从 raw text 复制到 organized version；之后只改 organized version。转换和未来用户触发的 AI 建议使用 organized version（若存在），但永不覆盖或丢弃 raw record。搜索同时匹配 raw 与 organized；普通结果不包含 Archive，Archive 自有搜索。

窄窗口采用 list-to-detail，返回恢复原列表滚动位置和选中条目。空 Inbox 使用克制的空状态，但固定底部 Capture 仍可用。

## 6. Review 回顾层

回顾是 D-0 已确认的积累感位置。R-1 推荐的可恢复贡献热力图（Heatmap）与路线回顾时间线（Timeline）在这里保留候选槽位，具体形式和默认范围由 IA-05 评审；本卡不重复反馈形式调研，也不批准评分或统计仪表盘。

```text
Planning / 回顾
├── 时间范围 → 历史事实列表 → 只读详情
├── 候选：日期热力图 → 当日已保存动作明细
└── 候选：路线时间线 → 有依据的完成 / 暂停 / 恢复记录
```

查看、筛选和展开均不修改 `activeRouteId`、`currentStepId`、路线生命周期、步骤或快照。缺历史事件就显示无可用记录，不从锚点推算专注时长、不制造次数；空白中性，不表示失败、欠债或需要补卡。不得加入连续天数、积分、排行榜、奖励或自动建议。

Capture 默认归属于 Inbox。本稿不从捕获时间推断它属于哪条路线，也不为回顾展示给路线追加捕获事件。若要显示捕获历史，可只读进入 Inbox 查看；关联规则须独立评审且不破坏“捕获只新增条目”。详情默认避免铺开敏感原文。

Guide 的完成反馈仍只在本地写入成功后短暂显示“步骤已完成”，随后直接显示下一动作；末步转安全空态，不出现下一条建议。

## 7. 任务流位置与整组推进

术语表的共同建议为：Project 可选包含 Route，Goal 可选关联 Route；Route 包含有序 Step，Task 是 Step 的 Planning 视角。没有 Project/Goal 的单任务或任务流照样使用。任务流（Task Flow）存蓝图，一次运行用一条 Route 承载；没有 Project → Goal → Task 的强制目录。

```text
Planning / 路线与任务流 / 任务流
  → 查看有序蓝图（可显式编辑）
  → 用户点“开始整组”
      → 若有该蓝图未完成实例：明确“继续本次”，恢复同一实例
      → 否则生成新的 Route 实例
  → 按 Planning 切换流程保存旧路线锚点、确认唯一活动路线
  → Guide 显示第一步 / 原保存步骤
  → 每次显式完成当前步并保存成功，直接显示下一步
  → 最后一步完成，Route 和历史保留，两个执行指针清空
  → 再运行必须回 Planning 明确点“再开始一次”
```

“一键推进整组”省去每一步重新选任务和额外“继续”按钮；不会一键完成全部，不会串联多条 Route 自动激活，也不会在日期到来时自动启动。尚未准备好的蓝图保持可编辑草稿；生成或切换失败不进入新 Guide、不显示已开始。重复点击需要只产生一次运行结果，不能创建多个看似相同的待办实例。

模板编辑仅影响未来实例；实例的执行、锚点、完成历史独立保留。任务页/日历显示已明确创建的本次实例步骤，任务流蓝图保留在管理页，不与待办重复显示。这个蓝图/实例方案仍是 C-03 推荐选项，不是数据库实现承诺。

## 8. 专注模式与桌面挂件

专注模式（Focus Mode）是用户显式进入后“隐藏主窗口和所有主菜单、只保留桌面挂件（Desktop Widget）”的 Guide 显示形态。普通 Guide 保留主窗口与固定模式切换；专注模式进一步改变窗口可见性，模式权限与路线状态不变。

```text
Guide 主窗口 → 明确“桌面专注”
  → 确认挂件可用后隐藏主窗口和全部主菜单
  → 桌面仅留同一个 Guide 的当前动作
  → 退出 / 关闭挂件 → 恢复主窗口 Guide 的同一步
```

建议挂件包含当前动作、完成标准、不要做边界、安静的路线/步数上下文、完成/卡住/暂停/捕获及退出入口。只显示一个动作；回退动作替换原动作，完成回退后回原步骤。紧凑窗口若需要展开，完成前必须可读到必要标准，不能只剩一个无上下文的勾选按钮。动作权限与展开细节交 IA-04，不在此决定尺寸、颜色或高保真外观。

Capture 在挂件中保持可达；打开紧凑面板并保留原动作语境，成功后回同一挂件动作，失败保留文字，取消不写入。捕获只新增原文与时间，不改执行状态。主窗口保留现有固定底部 Capture；挂件是待评审的另一表面，不声称现有底栏规范已经自动适用到小窗口。

“暂停并选择其他路线”先写完整暂停锚点（Pause Anchor），成功后恢复主窗口 Planning 的路线恢复区；原路线仍 active，选择替代路线前不切换。无活动路线时挂件显示进入 Planning 为主入口、捕获为次入口；最终步完成后同样进入此空态，不自动隐藏空态或启动另一条路线。

挂件创建失败则保留主窗口 Guide；关闭挂件默认恢复主窗口，不等于退出应用或丢失锚点。应用重启恢复以 `activeRouteId` 为准，建议先回主窗口 Guide，桌面专注仍由用户明确进入。托盘（Tray）和全局快捷键（Global shortcut）作为救援入口回到同一 Guide；外围都不能选择路线。

挂件是新增 v2 设计候选；[实施计划](../IMPLEMENTATION_PLAN.md) 的现有 MVP-2 只承诺托盘、快捷键、可选启动，不代表挂件已承诺或已实现。D-2 确定交互后由 E-1 评估发布阶段。需要验证主窗/挂件同源、重复完成防护与关闭后可恢复，不能引入第二状态机。

## 9. Planning / Guide 关系与关键流程

### 9.1 普通模式切换

```text
用户点击 Planning
  → 保存/保持当前呈现上下文
  → 按 §2.3 打开恢复区、首次日历候选或最近 Planning 目的地
  → 不暂停、不完成、不改变 activeRouteId

用户点击 Guide
  → 读取 activeRouteId
  → 有活动路线：显示其唯一 current Step
  → 无活动路线：显示 no-active-route state
```

### 9.2 暂停并选择其他路线

```text
Guide：Pause and choose another route
  → 原活动 Route 写入完整 Pause Anchor
  → 写入成功后进入 Planning / Routes / Paused 聚焦
  → 原 Route 仍为 active，尚未替换
  → 用户明确 Resume 另一条 Route
      → 切换时再次确保旧路线的当前上下文已持久化
      → 原子确认旧 Route 为 paused、新 Route 为唯一 active 和对应 currentStepId
      → 回 Guide 显示新 Route 的锚点或当前未完成 Step
  → 用户取消/返回 Guide
      → 原 Route 与当前动作保持不变
```

若锚点写入失败，留在 Guide，保留当前动作并显示简洁错误；若后续 Planning 切换写入失败，则留在 Planning 显示失败且旧执行状态完整不变。Guide 永远不显示候选路线。

### 9.3 完成、卡住、捕获

- Complete action：持久化成功后，非末步直接显示下一 Step；末步完成并保留路线、步骤和历史，清空 `activeRouteId` 与 `currentStepId`，转入 no-active-route state。写入失败保留原动作，不显示成功。
- Stuck：有 fallback 时只显示该单一回退动作；完成 fallback 后返回原 Step，不完成、跳过或替换原 Step。无 fallback 时只允许一句话记录 block，自动保存完整锚点，并提供返回或暂停两种选择；锚点失败不显示已暂停。
- Capture：从固定底部操作栏打开抽屉/窄屏面板；写入 raw text + timestamp 成功后回到原页面、原动作和滚动位置；失败保持输入与上下文。只新增 Inbox Entry，不改变任何执行状态或既有快照。

重启时先读 `activeRouteId`：为空则空态；非空只恢复该路线最新有效执行快照，无锚点时用该路线保留的当前未完成步骤，不因其他路线锚点更新而抢占。受保护步骤被显式删除形成断引用时，历史仍保留，转 Planning 显式解决，不能跳到无关路线或步骤。

## 10. AI、主动性与背景能力的位置

### 10.1 AI 建议级

AI 只出现在 Planning 的明确上下文中：Inbox 整理、Route/Task Flow 编辑或用户主动请求的分解建议。它的输出先作为可审阅草稿/建议，用户确认后才写入。Guide 不显示 AI 建议，不要求网络，不依赖 AI 才能完成 MVP-0 至 MVP-2。

禁止 AI 自动：选择活动路线、排序任务、安排日期、改变 Step 顺序、替换 fallback、修改 raw capture、在后台发送通知或推断用户状态。

### 10.2 主动性功能

“主动性”限定为界面提供稳定、低成本的入口，而不是系统替用户做决定：固定 Capture、恢复上次 Planning 位置、明确的暂停后聚焦 Paused、Widget/Shortcut 回到当前 Guide。这些入口可减少寻找成本，但不自动产生执行决策。

### 10.3 背景能力

背景能力只负责 Windows 壳层存在与本地可靠性：托盘、快捷键、可选启动、原子持久化、恢复与本地事件记录。它们不在后台改路线，不弹出打断通知，不创建自动任务，不改变 `activeRouteId`。
