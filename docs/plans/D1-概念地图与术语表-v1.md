## 2. 概念地图与共同候选基线

以下是关系图；“包含”“关联”“投影”“生成”是不同关系，不应读成一棵强制填满的目录树。

```text
项目（Project）──可选包含──路线（Route）──有序包含──步骤（Step）
目标（Goal）────可选关联──Route
步骤（Step）──1:1 的 Planning 用户视角──任务（Task）
任务（Task）──同一集合的投影──日历视图（Calendar view）/ 任务列表
                                  └──按项目 / 按目标分组
任务流（Task Flow）──保存有序步骤蓝图
       └──用户在 Planning 明确新开一次──生成一条 Route 实例

Route ──保留多个──执行快照（Execution Snapshot）
                    └──用作暂停锚点（Pause Anchor），不等于实时状态
捕获（Capture）──只新增──收集箱（Inbox）中的原文记录

板块 / 大类（Section；原需求中的 Board）是导航分区：
Planning ──任务 / 路线与任务流 / 收集箱 / 回顾；归档为次级入口
Guide ──仅 activeRouteId 指向路线的当前 Step
专注模式（Focus Mode）──隐藏主窗口，只留桌面挂件（Desktop Widget）
                       挂件呈现同一 Guide 动作，不另建执行状态
```

共同建议：Task 是 Step 的 Planning 用户视角；单个任务由单步 Route 承载，多个有序任务由多步 Route 承载。Project 保留现有“每条 Route 至多一个项目”的规则；Goal 建议先作为 Route 的可选方向文字。两者不互相包含，任务通过所属 Route 继承项目/目标显示。Task Flow 保存蓝图：没有未完成实例时，用户明确开始产生新的 Route；已有本次未完成实例时显示明确的“继续本次”。模板编辑不回写旧实例。以上是设计建议，不假定已有数据库字段或迁移已经完成。

模糊意图可先留在 Inbox，整理成 Goal；已明确动作但缺完成标准的内容可在 Planning 保留为草稿步骤，补齐后才可开始引导。规划侧排列和执行顺序分离：日历按日期显示、任务列表按稳定视图顺序显示，Guide 始终按 Route 内的步骤顺序推进。

例子：“毕业录音”是 Project，“交付可试听样片”是 Goal；Route“准备一次人声录制”包含检查输入、试录和回放等 Step，在任务页各显示为 Task。“晨间洗脸”是可独立存在、无需 Project/Goal 的 Task Flow；本次开始后是一条 Route，完成一次不会自动生成或激活下一次。


## 3. 术语定义与边界

### 3.1 Route（路线）

- 定义：有稳定身份、标题、生命周期、有序步骤与保留历史的执行计划，回答沿哪条路径推进。
- 边界：不是项目容器或目标结果；任务是路线中的步骤投影。任务流描述可复用蓝图，Route 描述一次实际执行。
- 层级：可选属于一个 Project；包含有序 Step；草稿可尚未完整，开始引导前须有可执行的未完成步骤。建议可带 Goal 文字。
- 排列：内部由用户在 Planning 定义步骤顺序；路线列表分组不改变内部顺序。最多一个 Route 为 active。
- 生命周期是分支而非单向链：draft 可显式激活；active 与 paused 可经明确切换往返；活动路线完成末步直接成为 completed。archived 是可逆保留状态，不表示完成必须先暂停或自动归档。已开始、未完成且非前台的路线保留 paused 和返回锚点；归档/恢复不可隐式激活。

### 3.2 Step（步骤）

- 定义：Route 的有序动作单元，包含当前动作（Current action）、完成标准（Completion standard）、不要做边界（Do not do boundary）与至多一个预写回退（Fallback）。
- 边界：Task 是同一步骤的 Planning 用户视角；动作是步骤的文字内容，不另建实体。草稿不等于已准备好执行。
- 层级：只属于一条 Route；完成和历史状态以该步骤为准。任务流蓝图的步骤定义在生成实例后才成为本次 Route 的 Step。
- 排列：按 Planning 明确的顺序；Guide 展示活动路线当前未完成步骤。回退占用同一动作位置，完成后回原步骤；原步骤只可按其完成标准显式完成。

### 3.3 Execution Snapshot（执行快照）

- 定义：与 Route 关联的不可变历史返回上下文，不是当前应用执行状态（Application execution state）。
- 边界：不替代持久化的步骤状态，也不是一份会被 Capture 更新的“当前页面缓存”；暂停锚点是其恢复用途。
- 层级：一条 Route 可保留多个 Snapshot。内容含 route ID、step ID、当前动作、完成标准、不要做边界、回退（若有）、暂停时间及可空备注。
- 排列：按保存时间保留历史，每次暂停或路线切换新增。重启先查 `activeRouteId`：为空显示安全空态；存在时只查该路线最新有效快照，无可用锚点时依据该路线保留的当前未完成步骤。若因显式删除形成无效恢复引用，须在 Planning 由用户解决，不跳到无关步骤或其他路线。

### 3.4 Pause Anchor（暂停锚点）

- 定义：确保能回到原动作及其上下文的返回锚点（Return anchor），由完整 Snapshot 承载。
- 边界：不是可选的暂停备注（Pause note）或简单书签；备注留空不影响锚点生成和恢复。
- 层级：属于路线执行历史，不另建平行锚点状态；暂停、切换前由本地存储确认保存。
- 排列：恢复使用该路线最新有效锚点，旧锚点不被覆盖；“暂停并选择其他路线”先存锚点，用户尚未选择替代路线时原路线仍 active。

### 3.5 Capture（捕获）

- 定义：快速保存原始文字（Raw text）与原始时间戳，不打断当前执行位置。
- 边界：不是任务创建、暂停、自动分类或 AI 规划；Capture 不向路线/步骤/既有快照追加信息。
- 层级：动作只新增一个收集箱条目（Inbox Entry）；后续整理另在 Planning 明确进行。
- 排列：Capture 动作本身无执行顺序，条目按捕获时间呈现。保存确认后回原动作、页面与位置；失败保留输入并留在捕获面板，不能显示成功。
- 状态隔离：`activeRouteId`、`currentStepId`、路线生命周期、步骤完成、既有快照均不改变；无活动路线时也不创建或激活路线。

### 3.6 Inbox（收集箱）

- 定义：保留捕获原始记录和可选整理版本（Organized version）的 Planning 内容区。
- 边界：不是任务池；未经转换的想法不是 Task。归档（Archive）是可逆保留位置，不能把原文转成任务后自动丢弃。
- 层级：Planning → Inbox → Entry；首次整理从原文复制，后续只改整理版；转换为 Route/Step 保留原文及时间。
- 排列：建议按捕获时间倒序；保留现有全部/未整理/已整理筛选，本地搜索原文与整理版。归档记录不混入正常结果。

### 3.7 Planning mode（规划模式）

- 定义：唯一允许创建、编辑、组织路线与步骤并明确选择活动路线的交互模式。
- 边界：不是自动规划器，也不以切入模式本身暂停或激活路线；浏览与执行选择分离。
- 层级：现有 Routes/Inbox/Archive 导航；本稿建议改为任务、路线与任务流、收集箱、回顾四主板块，归档次级、设置独立。
- 排列：主窗口保留固定 `Guide | Planning` 切换。普通进入恢复上次目的地；首次普通进入默认任务/日历属于候选变更，现规范为 Routes。暂停换路线与无活动路线的恢复入口仍打开路线恢复区，详见 IA §2。

### 3.8 Guide mode（引导模式）

- 定义：用户显式进入或应用恢复时呈现的执行交互模式，只读活动路线当前一步的内容并支持执行控制。
- 边界：非医疗状态，不由行为/个人信号推断；不列任务、项目、路线选项、优先级或 AI 建议。
- 层级：应用模式 → 唯一当前 Step；可在主窗口或专注挂件呈现。无活动路线时以进入 Planning 为主入口、捕获为次入口。
- 排列：当前动作最突出，其次是可见的完成标准和不要做边界；完成、卡住、暂停、捕获保持稳定。完成非末步后持久化成功即显示下一步；末步完成则保留路线并清空两个执行指针，不自动启动另一条。

### 3.9 Project（项目）

- 定义：可选组织容器，容纳相关 Route；沿用现有规范。
- 边界：Project 组织范围，Goal 描述结果，Task Flow 规定可重复的顺序；项目本身没有可执行动作。
- 层级：一个 Project 可含多条 Route；一条 Route 至多一个 Project，也可未分配。任务视图通过 Route 展示项目归属，不另设冲突归属。
- 排列：路线按项目分组，组内 active → paused → draft；paused 按最近暂停排序。未分配单列；改归属只改变组织，不改执行、步骤或锚点。

### 3.10 Goal（目标）

- 定义：希望达成的结果或方向，例如“交付可试听样片”。建议先作为 Route 的可选目标文字，同文字可用于任务视图分组。
- 边界：目标允许较模糊，不能作为 Guide 动作；它不是项目容器、完成标准或截止时间。模糊想法可先留在 Inbox，再在 Planning 澄清。
- 层级：Route 可带一个目标文字，任务继承展示；项目与目标无强制嵌套，没有目标的 Route 仍可执行。独立 Goal 实体属开放选项。
- 排列：按用户明确的目标筛选/分组；未设置目标单列。分组按文字稳定排序，不据此决定执行优先级。

### 3.11 Task（任务）

- 定义：建议统一为 Step 在 Planning 中的用户称呼；一个任务条目对应一个 Step，以所属 Route 和 Step 的身份引用同一记录。
- 边界：Task 不是 Inbox 原始想法、不是笼统 Goal、不是 Route 的第二份状态；复杂工作先在 Planning 拆成多个有标准的任务。
- 层级：独立任务使用单步 Route；多步工作使用多步 Route。任务继承路线项目/目标，可带候选日期属性。这里定义产品映射，不承诺数据库表名。
- 排列：独立任务页只列任务，日历/按项目/按目标均投影同一集合；执行仍按 Route 中 Step 顺序。非当前步骤不能从任务页勾选绕过路线；开始一个条目是显式选择所属路线并返回其当前步骤。
- 覆盖边界：草稿步骤保留在任务页并标明尚未准备好；已完成可切到完成筛选；归档默认只在归档入口。蓝图尚未生成的步骤不是本次待办，不重复算作任务。

### 3.12 Task Flow（任务流）

- 定义：固定顺序、可重复整体推进的任务编排，例如“晨间洗脸”。D-0 已确认“一键推进整组”，每次完成当前步骤后直接呈现下一步。
- 边界：Project 表示归属，Task Flow 表示重复顺序；Route 是某次执行的计划和历史。不会一键标记整组完成，也不以一串 Route 接力而绕过末步不自动激活的规则。
- 层级：建议采用蓝图 + Route 实例。蓝图有有序步骤定义；用户明确开始生成一条新 Route，并走 Planning 激活流程。项目/目标可选，不是启动前置。
- 排列：蓝图内固定步骤顺序；蓝图库按名称，历史实例按开始时间倒序，均为候选视图规则。每次实例独立保留步骤完成、锚点与历史。
- 复用规则：同一蓝图尚有未完成实例时，入口显示“继续本次”，从保存位置恢复；本次完成后，“再开始一次”须回 Planning 明确触发。编辑蓝图不覆盖旧实例，不自动重置已完成步骤。

### 3.13 Board / Section（板块 / 大类）

- 定义：Planning 的导航分区，建议对外统一称“板块”；Board 是原需求中的泛称，不表示看板状态模型。
- 边界：不是 Project 或 Goal 容器；日历、列表、按项目、按目标是同一任务集合的排列方式，不是不同任务存储池。
- 层级：Planning → 任务 / 路线与任务流 / 收集箱 / 回顾四个主板块；归档次级、设置应用级；“任务”下含日历主视图与独立任务列表页。
- 排列：四板块固定顺序，不按用户行为自动重排；主窗口 Guide 隐藏板块导航。

### 3.14 Calendar view（日历视图）

- 定义：任务板块的主视图，按日期组织同一任务集合，并同页保留无日期区。
- 边界：不把 Project、Goal、Route 标题当成额外任务；日期字段属新增设计候选，不能假定现有数据已有日期。
- 层级：Planning → 任务 → 日历。与独立任务页共享条目；没有日期的历史步骤直接进入无日期区，无需补填日期或迁移成今天。
- 排列：候选日期为计划日期，可选时刻；有日期无时刻放当日全天行，有时刻按时间排；完全无日期进固定无日期区。同一天按时刻、所属路线、步骤顺序稳定排列，日期不重排 Route。截止日期如何区分见 C-05。

### 3.15 Review（回顾）

- 定义：Planning 内查看已持久化历史事实的区域，回答做过什么、从哪里回来。
- 边界：不是分析仪表盘、评分或自动建议器。R-1 的热力图、时间线均为候选，不在本卡批准计时、补卡或统计体系。
- 层级：Planning → 回顾 → 历史明细；热力图与时间线从本地可验证历史投影。不把 Capture 自动关联到某路线，也不为展示改写快照。
- 排列：时间线按时间倒序，历史日期视图按日聚合；无记录为中性空白。缺少历史事件时显示无可用记录，不用快照推算专注时长或伪造完成次数。

### 3.16 Focus Mode（专注模式）

- 定义：用户显式进入后隐藏主窗口和全部主菜单，仅留桌面挂件呈现当前 Guide 动作的显示方式；这是 D-0 要求的桌面专注形态。
- 边界：普通 Guide 已减少选择，但仍有主窗口；专注模式进一步改变窗口形态。它不改变模式内核、生命周期或活动路线，也不根据行为自动进入。
- 层级：Guide 的桌面呈现变体，与主窗口使用同一执行状态；无活动路线时仍可显示安全空态。
- 排列：挂件只有一个当前动作，完成标准和不要做边界仍可取得；执行入口不带路线列表。关闭/退出挂件恢复主窗口 Guide，同一步保持不变。

### 3.17 Desktop Widget（桌面挂件）

- 定义：专注模式下承载 Guide 的轻量窗口，显示关键上下文和稳定返回入口。
- 边界：是同一 Guide 的另一个呈现表面，不是第二个执行控制器；不能列路线、优先级、回顾图表或 AI 建议。
- 层级：Windows 外围窗口；新增 v2 设计候选。现有 MVP-2 只承诺托盘/快捷键/可选启动，挂件实现阶段由 E-1 评估后更新计划。
- 排列：当前动作最突出；候选支持完成、卡住、暂停、捕获，复用同一写入确认规则。紧凑空间的展开方式与操作权限见 IA-04，不能为缩小窗口隐藏必要完成上下文。
- 无活动路线：主入口打开 Planning，次入口捕获；捕获成功仍回空态，不激活路线。

### 3.18 辅助词

| 词 | 定义与边界 | 层级与排列 |
| --- | --- | --- |
| Inbox Entry（收集箱条目） | Capture 的持久化产物；原文/时间不可变，整理版另存 | 属于 Inbox，按原始时间排列；不自动属于某 Route |
| Fallback（预写回退） | 每步至多一个预写替代动作；完成后回原 Step，不完成/跳过它 | 属于 Step；只有明确卡住时替换中央动作，不与原动作并列 |
| Current action（当前动作） | 当前 Step 的可执行文字，非独立任务实体 | 正常取原动作；卡住分支取预写回退；一次一个 |
| Do not do boundary（不要做边界） | 当前 Step 的限制说明，不是额外任务 | 属于 Step 和锚点上下文；跟随当前动作，不参与排序 |
| Active / Paused route（活动 / 已暂停路线） | 前台路线 / 已开始且非前台的未完成路线，不等于所有待办 / 所有未完成 | 属于 Route 生命周期；由唯一指针约束；paused 列表按最近暂停排序 |
| Archive（归档） | 可逆保留位置，不是删除或新副本 | 跨路线和捕获的次级视图，保留原归属与引用；按归档时间查看 |

## 5. 权限、方案取舍与交接

| 行为 | 允许的变化 | 不得发生 |
| --- | --- | --- |
| 任务列表 / 日历 / 项目目标视图切换 | 展示、范围与筛选偏好 | 改执行顺序、自动激活、复制任务状态 |
| Planning 明确编辑日期/项目/目标 | 对应组织元数据，保存成功后确认 | 改活动路线、步骤完成或快照 |
| Capture | 仅新增原始 Inbox Entry | 修改任何执行字段、原快照或路线历史 |
| 暂停并选择其他路线 | 先完整存锚点再入 Planning | 未选择替代路线就换掉原 active |
| Planning 明确切换 | 先保存旧路线，再原子确认旧 paused / 新 active 及当前步骤 | 写入失败时部分切换，或从 Guide 直接切换 |
| 回顾 | 读取可验证历史、改变查看范围 | 自动关联捕获、伪造计时、修改当前状态 |
| 归档 / 显式删除 | 可逆归档；删除须用户确认并解决受保护引用 | 自动清理、隐式删除、自动恢复其他路线 |
| AI 建议 | 生成待审内容，用户确认后执行对应 Planning 编辑 | 隐式修改、激活、自动排期或覆盖原文 |

候选结构比较：

- 推荐：Task = Step 的用户视角，单步路线容纳独立任务。保留现有执行真相，降低双状态同步负担；代价是 Planning 必须解释为什么多步路线中的后续任务不能越过当前步骤直接完成。
- 备选：Task 独立，Step 引用 Task。跨路线复用灵活，但同一任务的完成如何影响多次执行需另定规则，E-1 必须评估历史与迁移成本。
- 备选：只暴露 Route，把任务藏在路线详情中。迁移较小，但不满足独立任务页和日历列全部待办的需求，因此不作为 D1 推荐。

D-2 先使用同一推荐关系做交互验证，不能在不同页面各造 Task 定义。E-1 负责字段、迁移和事件可用性调查；不从本文推断已完成实现。逐项验收脚本见 IA §11。
