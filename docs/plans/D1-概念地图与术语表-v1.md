# D1 概念地图与术语表 v1

- 状态：设计基线草案，供 D-2 交互设计与 E-1 影响评估使用
- 依据：`AGENTS.md`、`docs/PRODUCT_SPEC.md`、`docs/UX_DESIGN.md`、`docs/IMPLEMENTATION_PLAN.md`、`docs/research/R1-坚持与反馈机制调研.md`、D-0 已拍板方向
- 产品定位：在 Guide 内核上扩展 Planning 侧能力的本地优先执行连续性工具，不转化为通用任务仪表盘

## 1. 统一原则

1. Planning mode（规划模式）负责写入和整理路线；Guide mode（引导模式）只读取、执行、暂停和捕获，不重新规划、不重新选择、不要求用户解释状态。
2. `activeRouteId` 是唯一的前台执行真相。任意时刻最多一条路线为 active（活动中）；没有活动路线时，`activeRouteId` 与 `currentStepId` 均为空。
3. 执行层只给一个下一动作；积累感、统计与历史回看放在 Planning 的 Review（回顾）区域，且只读、不改变执行状态。
4. 所有用户内容默认保留。归档可逆，删除必须由用户明确发起并确认。
5. AI 仅为 user-triggered（用户触发）的建议级能力，属于 MVP-3 可选项；不自动规划、排序、激活或替换路线。

## 2. 概念地图

```text
Daily（执行连续性工具）
├── Planning mode（规划模式）——写入与整理
│   ├── 组织层：Project（项目）
│   ├── 意图层：Goal（目标）
│   ├── 执行层：Route（路线）
│   │   └── Step（步骤）
│   ├── 编排层：Task Flow（任务流）
│   │   └── 一组有固定顺序、可重复推进的步骤模板/实例
│   ├── 导航层：Board / Section（板块 / 大类）
│   │   └── Routes、Inbox、Review、Archive、Settings
│   └── 回顾层：Review（回顾）
│       ├── 可恢复贡献热力图
│       └── 路线回顾时间线
├── Guide mode（引导模式）——读取与执行
│   ├── activeRouteId（活动路线唯一指针）
│   ├── 当前一步 current Step（当前步骤）
│   ├── Execution Snapshot（执行快照）/ Pause Anchor（暂停锚点）
│   ├── Complete（完成）
│   ├── Stuck / Fallback（卡住 / 预写回退）
│   └── Capture（捕获）→ Inbox（收集箱）
└── Application shell（应用外壳）
    ├── Focus Mode（专注模式）——Guide 的呈现形态
    └── Desktop Widget（桌面挂件）——可选的轻量入口/当前信息呈现
```

关系约束：Project、Goal、Board / Section 只组织或解释内容，不拥有执行权；Route 才是可执行计划；Step 是 Route 的有序组成；Task Flow 是可重复的步骤编排，不是第二套独立执行状态；Execution Snapshot 是历史返回锚点，不是 live state（实时状态）；Capture 只新增 Inbox 记录。

## 3. 术语定义与边界

### 3.1 Route（路线）

- 定义：一条有标题、有生命周期、有序步骤和历史记录的执行计划；它回答“准备沿哪条路径推进”。
- 不等同于：Project（项目）不是路线，Project 只提供可选组织容器；Task（任务）不是路线，Task 是更小的工作对象；Goal（目标）不是路线，Goal 描述方向而不是执行顺序。
- 层级：Daily → Route；Route 包含 1..n 个 Step，并可选归属于一个 Project、服务一个 Goal。
- 排列：Route 内按 Step 的显式顺序执行；Planning 的 Routes 可按 status（状态）或 project（项目）分组，但分组不改变执行顺序。最多一条 Route 的 lifecycle 为 `active`。
- 生命周期：`draft`（草稿）→ `active`（活动中）→ `paused`（已暂停）→ `completed`（已完成）/ `archived`（已归档）。归档可逆；已开始但未完成且不在前台的路线为 paused。

### 3.2 Step（步骤）

- 定义：Route 中一个有序、可执行的最小动作单元，包含当前动作、完成标准、`Do not do` 边界和至多一个预写 fallback（回退动作）。
- 不等同于：Task（任务）可以是组织层面的工作对象或步骤的用户语言；Step 强调已进入 Route 后的执行顺序。Action（动作）是 Step 的内容，不是独立容器。
- 层级：Route → Step；一个 Step 只属于一条 Route。
- 排列：按 `position` 顺序排列；Guide 只展示活动 Route 的第一个未完成 Step。完成非末步后直接显示下一 Step。

### 3.3 Execution Snapshot（执行快照）

- 定义：与 Route 关联的不可变历史执行记录，用于保存暂停或切换前的完整返回上下文。
- 不等同于：Application Execution State（应用执行状态）是当前 live state；Snapshot 不是当前状态，也不能替代 Step 生命周期；Pause Anchor（暂停锚点）是 Snapshot 在产品流程中的用途/别名。
- 层级：Route → 多个不可变 Snapshot；每次暂停或切换新增一条，不修改旧记录。
- 排列：按保存时间形成历史；恢复时只取 active route 的最新有效 Snapshot，不取其他 paused route 的更新记录。
- 最小内容：route ID、step ID、current action、completion standard、`Do not do` boundary、fallback（若有）、暂停时间、可选用户备注。

### 3.4 Pause Anchor（暂停锚点）

- 定义：用户暂停后可准确回到原位置的返回锚点，即完整的 Execution Snapshot。
- 不等同于：Pause Note（暂停备注）只是可选文字；没有备注也必须有锚点。它也不等同于 Bookmark（书签），因为锚点承载执行上下文而非单纯位置。
- 层级：由 Snapshot 持久化承载，归属于被暂停的 Route。
- 排列：以最新有效锚点为恢复依据；历史锚点保留，不被新锚点覆盖或删除。

### 3.5 Capture（捕获）

- 定义：在不中断当前路线语境的情况下，快速保存一段原始用户文字及时间戳的动作。
- 不等同于：Capture 不是 Task 创建器、不是自动分类器、不是 AI 规划入口；它也不是 Pause，因为 Capture 不保存/改变执行位置。
- 层级：Capture action → Inbox entry（收集箱条目）；Planning 可为 Inbox 条目另存 editable organized version（可编辑整理版本）。
- 排列：按捕获时间排列；列表可优先显示整理版本，但必须始终保留并可查看 raw text（原始文本）与原始时间。
- 状态隔离：只允许新增 Inbox entry，不得修改 `activeRouteId`、`currentStepId`、路线生命周期、Step 完成状态或任何既有 Snapshot。

### 3.6 Inbox（收集箱）

- 定义：保存 Capture 原始记录及其可选整理版本的 Planning 一级内容区。
- 不等同于：Inbox 不是未分类任务列表，不自动转成 Task/Route；Archive（归档）是生命周期位置，Inbox 是内容入口。
- 层级：Planning → Inbox → Entry；每个 Entry 含不可变 raw record，可选 organized version。
- 排列：默认按 capture time 降序；本地搜索同时匹配 raw 与 organized 内容；提供 `All / Unorganized / Organized` 显式筛选；归档记录进入 Archive，不出现在普通结果。

### 3.7 Planning mode（规划模式）

- 定义：用户创建、编辑、组织、回顾 Route 与 Inbox，并明确选择活动路线的交互模式。
- 不等同于：不是 Guide 的“高级版”，不是自动规划器，也不是单纯设置页；只有 Planning 可列出和切换路线。
- 层级：Application shell → mode；内部目的地包括 Routes、Inbox、Review、Archive，Settings 独立于核心执行导航。
- 排列：通过固定 `Guide | Planning` segmented control（分段控件）进入；首次普通进入打开 Routes，后续恢复最近 Planning 目的地；暂停并选择其他路线时聚焦 Paused。

### 3.8 Guide mode（引导模式）

- 定义：只呈现活动路线一个下一动作并支持完成、卡住、暂停、捕获的执行模式；也是应用恢复时的安全呈现状态。
- 不等同于：不是医疗状态，不由行为或个人信号推断；不是任务列表、推荐器或路线选择器。
- 层级：Application shell → mode → one current Step。
- 排列：单栏焦点布局；当前动作 > 完成标准 / `Do not do` > 完成按钮 > 卡住/暂停；Capture 处于固定底部操作栏但不取代当前动作。

### 3.9 Project（项目）

- 定义：可选的组织容器，用于把相关 Routes 放在一起。
- 不等同于：Project 不代表执行前台，不等同于 Goal，也不自动拥有或生成 Route。
- 层级：Project → 0..n Routes；Route 最多归属一个 Project，也可以 Unassigned（未分配）。
- 排列：Planning 的 `By project` 视图按 Project 分组；项目内 active → paused → draft；Unassigned 单独一组。改项目只改变展示和组织。

### 3.10 Goal（目标）

- 定义：描述希望达成的方向或结果，用于解释 Project / Route 的目的，不直接充当执行队列。
- 不等同于：Goal 不是可勾选 Step、不是 deadline（截止时间）或 priority（优先级）；不得在 Guide 中要求用户重新解释或选择目标。
- 层级：建议为 Planning 语义层的可选元数据；一个 Project 可关联多个 Goal，Route 可引用一个 Goal（具体关系待 D-2/E-1 进一步确认）。
- 排列：Goals 仅用于 Planning 的理解与筛选，不决定 `activeRouteId`，不自动排序或激活 Route。

### 3.11 Task（任务）

- 定义：用户可理解的工作单元；在本产品中，最终进入执行的 Task 应被落地为 Route 中的一个或多个 Step，未整理的想法仍留在 Inbox。
- 不等同于：Task 不是新的执行状态机；Route 是执行上下文，Step 是其中的顺序动作，Task 是跨视图的用户语言/组织对象。
- 层级：建议为 Project / Goal 下的工作语义；执行映射为 Route → Step。避免同时维护一个独立 Task 状态与 Step 状态。
- 排列：Planning 可按 Project、Goal、Calendar 或 Route 视图呈现；Guide 永不列 Task。具体 Task 是否作为持久化实体留待 E-1。

### 3.12 Task Flow（任务流）

- 定义：一组有明确固定顺序、可重复整体推进的 Step 编排，例如“晨间流程”或“每日洗脸”。核心动作是一次激活后按序推进整组，而非每次重新挑选步骤。
- 不等同于：不是 Project 的别名，不是重复任务的散落集合，也不是自动执行器；Project 组织范围，Task Flow 组织顺序和复用方式。
- 层级：建议为 Project / Goal 下的可复用编排；一次运行生成或引用一条 Route，Route 再承载实际执行快照和完成历史。
- 排列：Flow 内按固定 position；Flow 实例按用户明确激活的时间或上下文排列。不得自动启动，不得绕过 Guide 的单动作约束。
- 当前基线：D-0 已确认“一键推进整组”为核心形态，并允许自然复用；是否采用“模板 + 运行实例”双层模型留待 D-2/E-1。

### 3.13 Board / Section（板块 / 大类）

- 定义：Planning 中的一级导航分区，用于降低寻找成本并承载一种主要查看任务；不是业务实体。
- 不等同于：Board 不是 Project、Goal 或 Kanban 状态板；Section 不拥有任务、路线或执行状态。
- 层级：Application → Planning → Board / Section → destination；建议基础板块为 Routes、Calendar、Inbox、Review、Archive，Settings 另置。
- 排列：板块按导航优先级固定排列；目的地内部再选择 status、project、calendar 等显式视图，不把所有视图误当成实体分类。

### 3.14 Calendar view（日历视图）

- 定义：按日期组织和呈现所有待办工作对象的 Planning 查看方式，包含有日期与无日期内容。
- 不等同于：不是新的执行队列、不是自动排期器、不是优先级计算器；日期展示不改变 Route / Step 生命周期。
- 层级：Planning → Calendar；Calendar 投影 Project / Goal / Task / Route / Step 的已有数据。
- 排列：按日期分组；无日期任务必须在同一视图内有明确的 `Unscheduled / 无日期` 候选区域或底部收纳区，不隐藏、不混入某个日期。具体呈现由 D-2 决定。

### 3.15 Review（回顾）

- 定义：Planning 内只读历史区域，用来查看“做过什么、如何从暂停点恢复”，提供积累感而不施加执行压力。
- 不等同于：不是 Analytics dashboard（分析仪表盘）、评分器、排行榜或自动建议器。
- 层级：Planning → Review → Heatmap / Timeline；数据来自完成事件、Snapshot、恢复事件和 Capture 历史。
- 排列：热力图按日/周/月聚合，时间线按时间排列；空白表示无记录，不代表失败、欠债或需要补卡。

### 3.16 Focus Mode（专注模式）

- 定义：隐藏主导航和竞争性信息、强化当前 Guide 动作的应用呈现形态。
- 不等同于：不是新的路线生命周期、不是计时器，也不是自动进入的用户状态；它不能改变执行状态。
- 层级：Application shell 的 presentation layer；默认承载 Guide 的单栏内容。
- 排列：当前动作居中为唯一主焦点；只保留必要的完成、卡住、暂停和 Capture 入口。

### 3.17 Desktop Widget（桌面挂件）

- 定义：桌面上的轻量只读入口，显示当前活动路线的关键上下文，并可把用户带回 Guide。
- 不等同于：不是第二个 Guide、任务列表或路线切换器；不提供重新规划、优先级选择或跨路线浏览。
- 层级：Application shell 外围的可选 MVP-2 Windows presence；数据来源仍是 active route。
- 排列：桌面置顶/托盘入口由系统布局决定；内容最多包含活动路线标题、当前动作摘要、返回应用入口。具体窗口大小和交互留待 D-2。

## 5. 视图投影与状态隔离

| 投影/动作 | 读取对象 | 允许改变 | 明确禁止改变 |
| --- | --- | --- | --- |
| By status / By project | Routes、Project、lifecycle | 可见分组偏好 | `activeRouteId`、生命周期、Step 顺序、锚点 |
| Calendar | Task/Step 的已有日期与未排期数据 | 可见筛选、视图范围 | 自动排期、优先级、路线状态 |
| Review | 完成事件、Snapshot、恢复事件、Capture | 时间范围、只读筛选 | 当前路线、当前步骤、快照、内容 |
| Capture | 用户输入 | 新增 Inbox Entry | 所有执行状态与旧快照 |
| Pause | 当前 Route/Step | 新增 Snapshot，进入 Planning 的显式分支 | 自动选择新路线 |
| Resume | 用户明确选定的 paused Route | 按保存顺序切换 active route | 在 Guide 中列出/猜测路线 |
| AI suggestion | 用户触发的 Planning 输入 | 生成待审建议/整理草稿 | 自动写入、排序、激活、替换路线 |

## 6. 开放问题清单

每个问题均留给用户评审与 D-2 使用；本表不把候选项当成已确认事实。

1. **Project 与 Goal 的持久化关系**：A. Project 可选关联多个 Goal，Route 引用一个 Goal；B. Goal 独立于 Project，Route 可同时引用多个 Goal；C. MVP-2 只保留 Goal 文案，不建立关系。
2. **Task 是否成为独立持久化实体**：A. 不独立持久化，Task 作为用户语言映射到 Step（推荐，避免双状态机）；B. 独立 Task，Route/Step 作为执行实例；C. 先独立存储但不做独立生命周期。
3. **Task Flow 的模型**：A. 模板 + 用户明确启动的 Route 实例（推荐）；B. 每次直接复制为新 Route；C. 只做同一路线的重复运行，不建立模板。
4. **Board / Section 的最终命名**：A. 板块（推荐，强调导航分区）；B. 工作区；C. 大类。是否对外统一使用一个名称，需在 D-2 文案中确认。
5. **Calendar 中无日期任务位置**：A. 同一视图固定 `Unscheduled / 无日期` 区域（推荐）；B. 日期网格下方候选抽屉；C. 独立二级页，但保留日历入口提示。
6. **Review 的一级导航位置**：A. Planning 一级板块，与 Routes/Inbox 并列（推荐）；B. Routes 内的二级页；C. 独立顶部板块但仍只读。
7. **Desktop Widget 的入口权限**：A. 只读活动路线并一键回 Guide（推荐）；B. 允许完成当前动作；C. 允许完成与 Capture，但不允许路线选择。
8. **AI 建议承载位置**：A. 仅 Planning 的 Inbox/Route 编辑上下文（推荐）；B. Review 中提供“整理建议”；C. 独立 AI 工作区。无论选项，均须用户确认后写入。

## 7. D-2 使用边界

D-2 可据此文档继续设计 Calendar、Unscheduled、Task Flow、Review、Focus Mode、Desktop Widget 与 AI 入口的交互，但不能在未解决开放问题前擅自固化数据模型。任何新增 UI 都必须维持 Guide 单动作、Capture 状态隔离、activeRouteId 唯一性和本地离线可用性。
